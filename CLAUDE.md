# ⚠️ HAND-MAINTAINED — no generator exists yet

**This file is written and edited by hand.** An earlier version of this banner
said it was generated by `tekadept-sync-ai-config` from `docs/conventions.adoc`
and the ADRs. That was false: `tekadept-sync-ai-config` generates OpenCode's
model/provider config at `~/.config/opencode/opencode.jsonc` from
`~/.config/tekadept/ai.yaml`, and contains no reference to this file,
`docs/conventions.adoc`, or `docs/adr/`. Running it would not regenerate
anything here.

Naming a real tool that does something else was worse than naming none — it
made a false claim checkable only by reading the script. Writing the actual
generator is GitHub issue #92.

**Until that generator exists, this file carries the risk it warns about.**
`docs/conventions.adoc` and `docs/adr/` are the sources of truth. When they
change, this file must be updated in the same commit, by hand, or it drifts.

That is not a hypothetical here. **This repository is the case study.** The
previous `CLAUDE.md` (preserved at `docs/legacy-CLAUDE.md`) stated that state
management was "BLoC/Cubit" while every file in the codebase used Riverpod. The
claim was copied from a January 2026 org-wide spec the code had long since moved
past. The drift was never corrected — instead a second file, `AGENTS.md`, was
written to tell agents *not to believe `CLAUDE.md`*.

It has already happened again, smaller. A "Known-red rings" paragraph in this
file claimed `just analyze` and `just bff-check` were failing for weeks after
both went green. During a session on 2026-08-28 that stale claim caused work to
be skipped twice, on the grounds that a check "would fail anyway." It has been
removed and replaced with the current state, and it is the reason to prefer a
generator over discipline.

If something here is wrong: fix `docs/conventions.adoc` or write an ADR, then
correct this file in the same change.


### Project: randoeats (Flutter + Drogon BFF)

**Concept**: "rand-o-eats" (always hyphenated in UI) — picks somewhere to eat,
in a 60s Googie retro-future voice. The Jetsons meets Lost in Space.

**Stack**: Flutter 3.44.0 via FVM (iOS, Android, Web), Riverpod for state and
DI, Dio for HTTP, Hive for local storage, `geolocator`, `google_maps_flutter`,
Firebase (Analytics/Crashlytics), and a C++/Drogon BFF in `bff/`
(`randoeats_bff`). Flavors: `staging` and `production` only.

**State management is Riverpod — `lib/blocs/` is a lie.** `flutter_bloc` is
not a dependency and there is no Bloc or Cubit in the codebase. The directory
name is a scaffold leftover. Every feature under `lib/blocs/<feature>/` is
three files: `<feature>_notifier.dart` (a `Notifier<FooState>` plus its
`NotifierProvider`), `<feature>_state.dart` (an `Equatable` state class with a
status enum), and `<feature>.dart` (barrel export). Reference implementation:
`lib/blocs/discovery/`. Do not "restore" BLoC on the strength of the folder
name, and do not rename the folder as a side effect of other work. See
ADR-0002.

**Layering**: this project does *not* use the canonical
`presentation/ -> application/ -> domain/ <- data/` structure from
`docs/conventions.adoc`. It uses `app/`, `screens/`, `blocs/`, `providers/`,
`services/`, `models/`, `widgets/`, `config/`. There is no `lib/repositories/`
— the old `CLAUDE.md` claimed one existed. Read `docs/architecture.adoc`
before assuming any structure.

**Dependency injection**: services are constructed in `lib/bootstrap.dart` and
injected via `ProviderScope` overrides declared in
`lib/providers/service_providers.dart`. No global singletons.

**The Places API key never ships to the client.** All restaurant data goes
through the BFF, which holds the key and calls Google. `PlacesService` uses Dio
against `https://api.randoeats.com/api/v1/restaurants` (override with
`--dart-define=RANDOEATS_API_URL=...`); `Restaurant.fromBff` parses the
response. Never add a direct Google Places call from Dart. See ADR-0003.

**No accounts, no server-side user data.** Ratings, recent picks, visited
places and settings live in Hive on the device only
(`lib/services/storage_service.dart`). There is no sign-in and no sync — a
reinstall loses the data. Any feature implying cross-device continuity
contradicts ADR-0004 and needs a superseding ADR.

**Tests mirror `lib/` path-for-path**: `lib/blocs/discovery/discovery_notifier.dart`
→ `test/blocs/discovery/discovery_notifier_test.dart`.

**Commands**: `just check` (read-only, fail-fast — run this before reporting
anything done), `just analyze`, `just test`, `just format`, `just test-one
FILE`, and for the BFF: `just bff-build`, `just bff-test`, `just bff-test-asan`
(AddressSanitizer + UBSan; deliberately not in `just check` because it roughly
doubles the wall time), `just bff-check`, `just bff-format`, `just bff-nuke`.

**`just check` is green and it is the verdict.** As of 2026-08-29 every ring
passes: `format-check`, `analyze`, `test` (346 Dart tests), and `bff-check`
(clang-format, the clang-tidy ratchet at 112, and 17 BFF unit tests). Run it
before reporting anything done, and do not assume a ring is red — the previous
version of this file claimed `analyze` and `bff-check` were known-red long
after both went green, and that claim caused work to be skipped.

**Two gaps remain between `just check` and CI.** `.github/workflows/main.yaml`
enforces a 60% coverage floor with no local equivalent (issue #93), and neither
`just check` nor the `check` workflow builds the BFF container image — a fully
green PR broke the deployable artifact that way on 2026-08-28. A green
`just check` still does not fully imply a green CI.

**Never weaken a recipe to go green.** The clang-tidy ratchet
(`scripts/tidy-gate.sh --max 112`) is a ceiling that only moves downward: fix a
new finding or suppress it at the call site with a NOLINT naming the check and
the reason. Do not raise the number.

**You are the local tier of a two-tier workflow** (see `docs/agent-loop.adoc`).
You work from packets in `docs/packets/`. `test/` is read-only to you during a
fix loop — never edit a test to make it pass. Six failed `just check` attempts
on a packet means stop and escalate
(`docs/packets/escalation-template.adoc`), not try a seventh approach.

**Definition of done**: `just check` green. A spec exists for the feature. An
ADR exists if this touched architecture. This file is updated by hand in the
same change if conventions or ADRs moved — there is no generator yet (#92).

**The backlog is GitHub Issues, not a file.** `BACKLOG.adoc` was retired in
ADR-0005 and is now a pointer containing no items. Wanted work is an issue,
prioritized with `priority:now` / `priority:next` / `priority:later`; work
decided against is filed and closed as `wontfix` so the reasoning stays
searchable.

**Spec Kit is installed.** `/speckit-*` commands live in `.claude/skills/`,
templates and scripts in `.specify/`, and per-feature working artifacts in
`specs/NNN-*/`. The constitution at `.specify/memory/constitution.md`
deliberately points at the ADRs rather than restating them. Four BFF features
are specced; 001 (test harness) is built, 002-004 are not.
